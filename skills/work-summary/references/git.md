# 通道 B：Git 采集

两套作者都要扫，不能互相替代：

| 用途 | 作者 |
|------|------|
| Markdown 日报正文 | **本机作者**：各仓 `git config user.name`（以本机全局/当前仓为准） |
| 纯文本三块 / 精简版 | **指定人**，默认陆长颖；用户点了别人再用别人 |

不要用本机名冒充陆长颖。若本机名就是陆长颖（或 git-authors 映射到同一人），扫一次，日报和精简版共用。

## 作者怎么对上

**本机作者：** `git config user.name`。再读 `E:\工作日记\git-authors.txt`，把该显示名映射到的 git 名一并 `--author`。

**指定人：** 按顺序取匹配名（去重后全部拿去 `--author`）：

1. 用户原话里的中文名（如陆长颖）
2. `E:\工作日记\git-authors.txt`
3. 本 skill `references/git-authors.example.txt`（仅当工作日记没有 git-authors.txt）

`git-authors.txt` 格式：每行一个 git `author.name`；可用 `显示名 = git名1, git名2`。

```
陆长颖
陆长颖 = 陆长颖, luchangying
```

`--author` 按子串匹配。中文名与拼音都要试；对上任一个即可，不要把同仓别人的提交算进来。

## 扫哪些仓

当前 Cursor 工作区里所有 git 根目录都要扫（含子仓），常见包括：

- `tms-bus` / `tms-base` / `tms-ui`
- 其它已打开的业务仓（如 SgmwBC、docs）

不要只扫当前聚焦的一个仓。某个仓当日无该作者提交，记一句「某仓无提交」，不要写成没干活。

## 时间窗

默认「今日」= 本地日历日，时区 `Asia/Shanghai`。

```text
--since="YYYY-MM-DD 00:00:00" --until="次日 00:00:00"
```

用户说昨天 / 某日则改日期。用 `--all`，避免漏掉只在远程分支上的提交。

## 命令（每个仓各跑一遍）

把 `<作者>` 换成映射表里的每一个名字；多名字就多跑几次再合并、按 hash 去重。

```bash
git log --all --author="<作者>" --since="YYYY-MM-DD 00:00:00" --until="YYYY-MM-DD+1 00:00:00" --pretty=format:"%h%x09%ad%x09%an%x09%s" --date=iso
```

有提交后再看改了什么（单条、控制篇幅）：

```bash
git show --stat --format=fuller <hash>
```

禁止把整份 diff 贴进日报。从 subject + 变更文件 + 少量 hunk 归纳业务事实。

可选：看该作者未提交改动是否与当日工作相关（`git status` / `git diff`），只作「明日计划」线索，未提交不要写成已交付。

## 从提交归纳成文

- 合并同一主题的多次提交（修同一口径的 amend/follow-up 写成一条）
- 合入 / 合并分支单独记「合入」，不要当成新功能
- 从提交能看出的「原来怎样、改成怎样」写成 **问题与解决方案**
- **明日计划**：昨日计划未完成项、提交信息里的「待/联调/脚本未执行」、某仓无提交但背景仍在跟的线、工作区未提交改动
- 没有提交时：不要写「无提交」对外；走无产出日口径，或纯文本写「核对/对齐/承接」（见主 skill）
